# Decisions

Choices made where the implementation plan left things open. Newest at the bottom.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-03 | **React 19** for the UI (the plan allowed plain TS or light React). | Team preference; chips, toolbar, quiz banner and walkthrough player are UI-state heavy. |
| 2026-11-03 | **Plain Three.js inside React**, not React Three Fiber. The scene lives in an imperative `SceneController` class (`frontend/src/viewer/controller.ts`) mounted by a thin `<Viewer>` component. | The plan's action executor calls controller methods directly (`highlight`, `isolate`, `focus`…). Keeping Three.js out of React's render cycle makes that straightforward and avoids one more dependency. |
| 2026-11-03 | **Vite 8 + TypeScript 7**, created by hand rather than `npm create vite`. | Same layout as the official `react-ts` template, minus ESLint for now. |
| 2026-11-03 | **One `.env` at the repo root**, shared by backend (`pydantic-settings`) and frontend (`envDir: '..'`). | One place to configure; Vite only exposes `VITE_*` variables, so secrets stay server-side. |
| 2026-11-03 | **venv + pinned `requirements.txt` / `requirements-dev.txt`** for Python. | Works on every machine with no extra tools; `uv` can replace it later without code changes. |
| 2026-11-03 | **`httpx2`** for the FastAPI test client. | Starlette deprecates `httpx` in the test client. |
| 2026-11-03 | **Ports:** frontend 5173, backend 8000. | Tool defaults. |
| 2026-11-03 | **No Docker or Kubernetes for now.** Add a single backend Dockerfile only if we deploy. | Local-first project with a laptop live demo; containers add setup cost without benefit until deployment. |
| 2026-11-08 | **21 registry structures from the 40 GLB meshes** (`assets/structures.json`). A structure lists every mesh it covers, e.g. `aortic_valve` → 3 leaflets, `pulmonary_veins` → 4 veins. Papillary muscles and cardiac veins are one structure each. | Students talk about structures, not leaflets or branches; grouping keeps the quiz and reference resolution at that level. Splitting a group later only adds IDs. |
| 2026-11-08 | **Interventricular septum and myocardium left out of the registry.** | Neither is a separate mesh in Z-Anatomy (see `docs/asset_prep.md`). Add them back if the septum is split out in Blender. |
| 2026-11-08 | **Neighbor links are two-way**, and structures may carry an optional `notes` field for model caveats. | Two-way links make retrieval expansion predictable and are easy to check; `notes` keeps known gaps (missing leaflets, partial vessels) next to the entry they affect. |
| 2026-11-08 | **`resolved_refs` is a list of `{word, start, structure_ids}`**, not the plan's word → ID map. | A map can't hold "compare this and this": both words are the key "this". `start` (character offset) lets the UI link each word to its chip. |
| 2026-11-08 | **Stub `POST /api/command`** returns sample responses from `assets/fixtures/` until the agent exists. | The frontend can integrate against the real endpoint and format now; the fixtures double as frontend mock data and are checked against the schema by the tests. |
| 2026-11-10 | **Selection lives in a small store outside React** (`frontend/src/selection/store.ts`); components read it with `useSelection`. | The scene controller and, later, the action executor change the selection without going through React. |
| 2026-11-10 | **A plain click on empty space clears the selection**; a Shift-click on empty space does nothing. Esc also clears. | Matches common 3D and file-manager behavior, and a missed Shift-click shouldn't wipe a multi-selection. |
| 2026-11-10 | **The click log only holds clicks for structures that are still selected.** Removing a structure (Shift-click or chip ×) drops its click; a plain click restarts the log. | `click_events` and `selection` in the request always describe the same set, so reference resolution never sees a click for something the student deselected. |
| 2026-11-10 | **Viewer colors are set in the frontend** (`viewer/colors.ts`) by registry `group`, with red for oxygen-rich and blue for oxygen-poor vessels. All meshes of a structure share one material. | The GLB's exported materials are mostly grey. One material per structure makes it highlight as a unit. |
| 2026-11-10 | **Selected structures turn gold**; hover shows a name tooltip. | Gold stays readable on both the red and the blue vessels. The tooltip will need an off switch for quiz mode, where it would give away the answer. |
| 2026-11-10 | **A hovered structure gets slightly bigger** and keeps its own color: about 5–6% larger around its middle, and thin structures also swell outward so vessels look thicker (`HOVER_GROWTH` in `viewer/controller.ts`). | Tried and dropped: a glow (too subtle, changed the color) and fading the other structures (the team didn't like the look). |
| 2026-11-10 | **The hover growth is drawn in the shader**, not by scaling the meshes, and the coronary vessels are drawn slightly closer to the camera while another structure is grown. | Picking keeps using the real geometry, so a grown chamber can't block the cursor from the vessels on it. Without the depth lift, a grown chamber swallowed those vessels. |
| 2026-11-10 | **Leader-line labels** name every structure that can currently be seen, in two columns beside the heart, with a "Labels" switch (on by default). Built as an HTML/SVG overlay in `viewer/labels.ts`, not Three.js' `CSS2DRenderer`. | The plan's `CSS2DRenderer` puts text on top of the structure, which covers small structures. Columns with lines keep the model clear and let labels be spaced so they never overlap. |
| 2026-11-10 | **A structure is labeled only while a point on it is visible**, tested by casting rays from the camera to a few sample points on its surface. | Otherwise labels would point at structures hidden inside or behind others. Hiding a layer makes the labels behind it appear without extra code. |
| 2026-11-10 | **Labels are clickable**: hovering one acts like hovering its structure, and clicking selects it (Shift adds). | Gives a second way to select small structures that are hard to click. Like the tooltip, labels must be off in quiz mode. |
| 2026-11-10 | **`three-mesh-bvh`** speeds up ray casting (a search tree per mesh). | Without it one ray tested all ~300k triangles: the label visibility check took ~260 ms and made rotation stutter. With it the check takes ~2.5 ms, and picking is faster too. |
| 2026-11-10 | **Structures panel** (`ui/StructurePanel.tsx`): the four layers with their structures nested under them, and an eye button on each row and each layer. It replaces the plan's row of layer buttons. | Several structures sit inside others (valves, papillary muscles), so students need to hide single structures, not only whole layers. |
| 2026-11-10 | **Hidden structures live in a store outside React** (`visibility/store.ts`), like the selection. `SceneController.setVisibility` writes to it. | The panel and the agent's `set_visibility` action then always agree, whichever one made the change. |
| 2026-11-10 | **The panel is a sidebar that the 3D view sits beside**, not an overlay on top of it. | The heart and its label columns re-center in the remaining space instead of being covered. |
| 2026-11-10 | **"Recenter" only moves the camera** (`SceneController.resetView`): back to the anterior view over 0.6 s, orbiting the heart. It leaves the selection and hidden structures alone. | The button was asked for as a way back to the starting position. The agent's `reset_view` action can call the same method; whether that action should also clear highlights and show everything is still open. |
| 2026-11-10 | **`Viewer` exposes a small handle** (`ViewerHandle`, via `ref`) for commands from the rest of the app. | The Recenter button lives in `App`; the action executor will need the same route to the controller. |
| 2026-11-10 | **Vitest** for frontend unit tests (`npm test`), used for pure logic such as the selection store. UI behavior stays on the manual checklist. | Selection order decides what "here" and "there" mean, so it is worth an automated check; Vitest reuses the Vite config. |
